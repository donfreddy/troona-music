# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install dependencies
flutter pub get

# Run code generation (required after changing Isar collections; the .g.dart files are committed)
dart run build_runner build --delete-conflicting-outputs

# Run the app
flutter run

# Lint / static analysis
flutter analyze

# Run all tests
flutter test

# Run a single test file
flutter test test/unit/player/queue_test.dart
```

Tests live in `test/unit/` (pure logic, blocs, repositories) and `test/widget/`. Shared player test doubles (`FakeAudioPort`, `buildTestPlayerBloc`, `testTrack`) are in `test/helpers/fake_player.dart`. The Isar tests run against the real engine, loading the host library shipped by `isar_plus_flutter_libs`.

## Architecture

**Feature-First + Clean Architecture.** Each feature under `lib/features/` is self-contained with three layers:

```
feature/
├── domain/       # Entities, Repository interfaces, Use Cases: pure Dart, no Flutter
├── data/         # Models, DataSources, Repository implementations
└── presentation/ # Pages, Widgets, Bloc/Cubit
```

App-wide services that are not a feature live in `lib/services/` (`audio/`, `scanner/`, `history/`).

### Key architectural rules
- The **Domain layer** has zero Flutter or third-party imports (`dartz` excepted). It only speaks to interfaces.
- The **audio engine** is isolated behind `AudioServicePort` (in `lib/features/player/domain/ports/`). The Domain never imports `just_audio` or `audio_service` directly.
  - `JustAudioAdapter` implements `AudioServicePort` (the real playback engine).
  - `AudioHandlerImpl` bridges `audio_service` (lock screen, notifications) to `AudioServicePort`. It delegates everything and has no business logic.
  - Wired together in `AudioServiceInitializer.init()`, called from `configureDependencies()` before the player is registered.
- The **equalizer** (`lib/features/equalizer/`, Android only) is the second importer of `just_audio`, behind `EqualizerPort`: `JustAudioEqualizer` owns the `AudioPipeline` (`AndroidEqualizer`, `AndroidLoudnessEnhancer` for Volume +) handed to `JustAudioAdapter`'s player. The phone tells its bands only once a song is loaded (`EqLayout`, saved so the next launch knows them at once); the curve is kept in Hz (`EqCurve`, presets at 10 anchors) and sampled at the phone's band centres, in 0.5 dB steps. `EqApplier` sends only what changed, one batch at a time, and sends everything again after a failure or a new audio session id (Android recreates the effects with their defaults). Avoid clipping lowers the player's volume by the highest band gain (`EqHeadroom`, `JustAudioAdapter.setTrim`), never seen in `volumeStream` or the saved session. `EqualizerProbe` guards against phones whose effects crash a load: a strike written before the first load of a launch and cleared once the bands are read; two launches in a row left with their strike (one may be the app killed at the wrong moment) and the equalizer is off for good (`UnsupportedEqualizer`, no dock item, no Settings row). It covers the first activation of a launch only: effects made again later (after a stop, a new audio session) are just_audio's. `EqualizerCubit` holds the settings and profiles (`SharedPreferences`), steps between presets, throttles drawing and bypasses everything while Compare is held (let go when the sheet closes, the switch changes, or Settings reset or restore). The sheet (`showEqualizerSheet`) opens from Now Playing's dock and Settings > Playback; its curve (`EqGraph`) is drawn with a finger, a double tap flattens a band, and a screen reader gets one slider per band.

### Dependency Injection
Uses **get_it** with **manual** registration in `lib/core/di/injection.dart` (`configureDependencies()`). The `injectable` package is listed as a dependency but annotations are not the source of truth: `injection.dart` is.
- Singletons: `PlayerBloc`, `TrackPaletteCubit`, `LikesCubit`, `SleepTimerCubit`, `TrackSelectionCubit`, `SettingsCubit` (shared by Settings and Home's offer card, provided with `BlocProvider.value`), `EqualizerCubit` (started at once, provided in `main.dart`), the audio port, the Isar data sources, `PlayHistoryRecorder` (started eagerly).
- Factories (new instance per mount): `LibraryBloc`, `HomeBloc`, `SearchBloc`, the detail blocs, `MaintenanceCubit`.
- Repositories and use cases are lazy singletons.

### State Management
`flutter_bloc` throughout. `PlayerBloc` and `LibraryBloc` are provided at the shell level via `MultiBlocProvider` in `app_router.dart`, making them available to all shell pages. `FullPlayerPage` is outside the shell and receives `PlayerBloc` via `BlocProvider.value`. Queue edits (`QueueEditEvent`) go through a single sequential handler so they apply in order. The bloc remembers the ids of the album, playlist or song the queue was built from: playing another song of that source jumps within the queue, and replacing a queue that still holds songs queued by hand (`Queue.hasAddedAhead`) emits a `QueueReplaced` notice, which the shell shows as a toast with Undo (`QueueReplaceUndone` restores the queue through `restoreQueue`). A queue that keeps both layers apart is issue #2.

### Navigation
`go_router` with a `StatefulShellRoute` wrapping the bottom-nav branches (`/home`, `/library`, `/search`, `/playlists`). Its container, `tabsContainer`, is go_router's indexed stack with heroes off in the hidden tabs: they stay mounted, and a flight on the root navigator (into Now Playing) would meet the same album cover in two tabs. `GlassSliverHeader` also turns heroes off in its content once more than half faded. The full player (`/player`) is a fullscreen `CustomTransitionPage` on the root navigator, outside the shell; it morphs from the mini player through Hero flights (`now_playing_hero.dart`), straight ones (`NowPlayingHero.flightTween` on all four heroes, both sides). The route fades nothing: the page fades its own layers, its background and tab bar over the first 45 % of the route animation (opaque on dismiss while the surface flies), the chrome and the stage (lens, arc, covers) later. A drag down moves the content only. The shell's pages drop 12 px once covered and rise back on dismiss as they show again (`NowPlayingCoveredDrop`). A finger on the ring widens the arc into the glass band and lifts the lens and the current cover by 6 % (`ProgressRing.lift`); with reduced motion the band still widens but nothing grows. Each press effect has its own curve for each way (an ease-out played backwards would end the release at full speed). While the content is dragged down, glass (the lens, the dock) keeps its opacity: a blur under an opacity layer samples that empty layer. The queue opens as a modal sheet over it (`queue_sheet.dart`).

Home leads with music: the resume card, at most one card about the app (`HomeSystemCard`: a new release, else the online extras offer), the quick chips, then Recently played; last week's recap card comes after it, and this calendar week's plays (from the daily totals) are the page's subtitle (`HomePage.subtitleOf`), not a banner; coming back on another day reloads the feed (`HomeResumed`). An offer on screen stays until answered, even if a release is found meanwhile. Home repeats neither the Library's artists nor the Playlists tab. No shortcut changes the Library's filter or sort except Search's See all of artists or albums, which opens the Library on that list. Home's Recently added row is the start of `RecentAlbumsPage` (`context.pushRecentAlbums`, `/home/recent/albums`, a sibling of `recent`, not nested), its See all: both take `RecentlyAdded.albumsOf`, an album coming when its newest song does (MediaStore's date added, as the songs), the cards being the library's own albums. Its grid keeps its heroes off until the page is in (`HeroesOnceIn`, which also reads the offstage frame a push measures heroes in): the row's covers would fly into it, some from off screen; a card still flies into its album. Both recent pages read the library through `LibrarySnapshotBuilder`: the last songs and albums loaded, a loader while there is nothing to show and more to come (the library still being read, or a scan over an empty one: a new install reads an empty database before its first scan), rebuilt only when those lists change (a scan's progress and the Library's search emit often).

Colours follow the place: the tab roots, Now Playing and playlist pages glow in the colours of the song playing (`TrackPaletteCubit`); album and artist pages in their own cover's (`CoverBackground`: the artist's downloaded photo, else their cover), opening in the playing colours and cross-fading to theirs. Both read colours through `CoverPalette`: one cache by image path (64 covers), checked against the file's modified time (an artist's photo is downloaded again to the same path), failures kept until the file changes, one read in flight per path. It decodes the file at 64 x 64 straight from its bytes (an `ImageProvider` waits 15 s on a broken file). Covers are stored per song and an album's is its first song's, so the album page shares the playing song's colours only when that song is the first; else it reads its own, close or equal. The artist page's background follows a photo downloaded or deleted while it is open (`onArtistArtworkUpdated`), as its header does.

The shell paints `AmbientBackground` behind the tab pages, which are transparent. A page pushed over a tab must be opaque, or the page below shows through it while it slides in, then vanishes when the slide ends: `app_router.dart` wraps such routes in `_overTab` (Settings, Privacy, Your listening, an artist's songs, Recently added, Recent albums); album, artist and playlist pages paint their own background.

Pages are edge to edge: content scrolls under the status bar and the floating tab bar (`SystemUiMode.edgeToEdge` in `main.dart`, `AppTheme.systemOverlay`; never `SystemUiOverlayStyle.light`, which paints the navigation bar black). Every scrolling page's header is a `GlassSliverHeader` (`lib/shared/widgets/glass_sliver_header.dart`), the first sliver of a `CustomScrollView`; no Material `AppBar` except the playlist editor's modal form. `GlassSliverHeader.largeTitle` for tab roots and pushed list pages (an iOS large title that snaps when left halfway); the plain constructor for heroes (album, artist, playlist), whose Play and Shuffle scroll away; Search pins its field (`pinnedBottom`) with no navigation row. The artist page has one layout and one height: the name and counts at the bottom left, Shuffle at the bottom right, at the same place with or without a photo, over their photo edge to edge (`background`, `stretch`) or, without one, over the glow of their cover (`_CoverGlow`: blurred once off screen and kept as a small image the header stretches, so nothing is filtered on screen). A photo found later fades in behind text that does not move. A downloaded photo flies from the round `ArtistCard` tapped into the header and back (`ArtistPhotoHero`: the circle opens into the rectangle while the plain photo cross-fades into the header's faded one, so neither end changes on landing); a cover does not fly, since the header shows it blurred. One card per artist on a page, as for `AlbumCoverHero`. A hero absent from the page's first frame never flies, so the artist page shows its header at once while it loads, from the artist and their songs as `LibraryBloc` groups them (Shuffle, the menu and the listening time whole from the first frame; the menu's Play next and Add to queue wait for the page's songs, most played first, so their order never depends on when they were asked) (`_fromLibrary`, as the album page does; a guest only, left out of `allArtists`, through `LibraryGrouping.artistOf`), and asks online info once the songs come (their titles match the photo). Both melt into the page through one mask (`_imageFade`); no second gradient darkens the image below the navigation row, or the two undo each other and the image ends on a line. The bar's compact title comes in only once the expanded content is down to `titleHandover` (20 %), so the two names never show at once (`titleOpacityAt`). The bar's glass has no hairline: its tint fades out over `softEdge` below it (the blur cannot fade: a `BackdropFilter` under a `ShaderMask` blurs nothing). Under the tab bar, the shell fades content into the background over `bottomBarInset`. The Library's Songs, Albums and Artists, when sorted by a name and at least `libraryIndexMinItems` long, get an alphabetical index down the right edge (`LibraryIndex`, `libraryIndexTexts` in `library_page.dart`): letters by `sortKey`, # for the rest. A letter jumps without building what lies above: every song row is one height (`SliverPrototypeExtentList`, its divider inside; the row's lines force a strut, `StrutStyle(forceStrutHeight: true)`, so a name mixing scripts, Latin and CJK, does not grow it), and grid cells are the cover plus the card's measured text (`CardGrid`, `AlbumCard.textHeight`, `ArtistCard.textHeight`, their lines held by the same strut), so the place of the nth item is known. Only the items built in the frame a list opens play their entrance (`_Entrance`; `EntranceFader(play:)` reads it once and keeps the same transitions either way, so a rescan neither replays nor remounts rows); the ones scrolling or the index bring in show at once. Tapping the tab already shown scrolls its root page to the top (`ScrollToTopOnReselect`, wrapped around the root pages in `app_router.dart`). Album and artist pages open with `context.pushAlbum` and `context.pushArtist`, in the current tab (never the Library's named routes, which switch tabs); Search's Recently added opens `RecentlyAddedPage` the same way (`context.pushRecentlyAdded`, a `recent` route in Home and Search, the two tabs that open it: Home's Recently added chip and Search's See all): the last `RecentlyAdded.limit` songs, newest first, in the order Search's five suggestions take (`RecentlyAdded.of`), without touching the Library's own sort; they hand the location they come from as `extra`, a plain string go_router can encode, so opening the page just below (an album's artist, opened from that artist) goes back to it instead of piling up copies.

### Storage
One Isar database (`isar_plus`), opened by `AppDatabase.open()` in `lib/core/database/`. Each data source declares its collections (`IsarLibraryDataSource.schemas`, `IsarPlayHistoryDataSource.schemas`) and `injection.dart` passes them in, so core never imports a feature. Adding a collection needs no migration.
- Library: tracks and playlists (`IsarLibraryDataSource`).
- Smart playlists: a playlist with `rules` (`SmartRules`, `lib/features/library/domain/entities/smart_rules.dart`, stored as JSON in `PlaylistModel.rulesJson`, a nullable field added without migration). `Playlist.isSmart`. Its songs are never stored: `SmartPlaylist.evaluate` works them out from the library, every song's daily plays (`PlayHistoryRepository.trackStats`, one read of `TrackDayModel`) and the liked songs, read together by `SmartPlaylistSource`, all three or an error (read as none, a history or liked songs would let every song into "never played" or "not liked"); days count today included, a song never played fails "last played over N days ago" and comes first in "played longest ago". The JSON is read leniently (`SmartRulesJson`): a rule of an unknown kind or out of bounds is dropped under any rule (that only narrows); under all rules, or when every rule is dropped, and for rules that cannot be read at all, the playlist keeps nothing (`SmartRulesJson.unreadable`, limit 0), never more songs than asked; a restore never replaces working rules with unreadable ones. Text rules match on `foldedKey` (case and accents folded, a leading "The" kept, unlike `sortKey`). A random sort gives each song a place drawn from the seed and its id, so a song coming or going leaves the others in order; `mostPlayedMonth` counts the last 30 days. A smart playlist takes no song added, removed or moved (the data source ignores adds, the repository refuses a reorder, the add sheet lists none) and keeps its rules on rename (`updatePlaylist` copies them, never for Likes). Its page (`PlaylistDetailBloc` with `smart`) evaluates on each load and again after each play recorded and each like (an error on a first load that cannot read, the songs kept on a reload), a random sort keeping the seed drawn when the page opened; rows have the song's own menu and no handle; the header's menu edits the rules or saves the songs shown as a playlist of songs, all or none (`PlaylistSaveAsRequested`). The editor (`openSmartPlaylistEditor`, `SmartEditorCubit`) is pushed on the root navigator, so the shell's floating bar does not cover it, as is the playlist editor (`PlaylistEditorPage`: its name alone, no cover, a new playlist named by `defaultPlaylistName`, "My playlist #N" past the names taken, selected so typing replaces it); templates are `SmartTemplate`, every choice a menu (`pickSmartRule`). Backups carry the rules (`BackupPlaylist.rules`); a restore matches smart playlists and playlists of songs by name separately.
- Play history: `PlayEventModel`, capped at 500 events (`lib/features/history/`). `PlayHistoryRecorder` records a play after 30 s of listening, or half a track shorter than a minute (`PlayCounter`). Home "Recently Played" reads it.
- Daily totals, never pruned, written in the same transaction as each play: `ListeningDayModel` (plays, listening time), `TrackDayModel` (plays per track per day), `TrackFirstPlayModel`, `ListeningHourModel` (plays per local hour, id `day * 24 + hour`). Days are `ListeningDay` keys (local calendar days since epoch). `backfill()`, before the recorder starts, fills each of these that is still empty from the stored events. The recorder writes listening time every 30 s, on a track change and at midnight. Your listening (`ListeningRecapCubit`, `GetListeningRecapUseCase`: any week or month, `RecapPeriod`; Home's card is last week) reads them. Its calendar fills days by fixed steps of plays (`PlayIntensity`, the same in every span); When you listen (`ListeningMoments`, weekday by quarter of the day) by steps relative to its busiest cell. A night counts for the evening before, so a span's hours run from 6:00 on its first day to 6:00 after its last; each cell is divided by how many of its weekday the span has lived (since the history began, up to today). `RecapClock` refreshes the cubit when the app comes back, so Home's card moves on to the new week. Backups carry the hours (`BackupHour`); a backup made before them adds the hours of the plays it restores. Both draw `HeatCell`. Share turns the span into a story, `RecapStory` (360 x 640 captured at 3x, fixed font size and no motion), previewed in `RecapShareSheet` then written to the temporary directory, shared and deleted. The monthly Replay playlist reads the daily totals too (`CreateMonthlyReplayUseCase`, run once per month from `AppShell`; the handled month is kept in `SharedPreferences`).
- Playback session (queue, position, and the album, artist or playlist it was started from: `QueueOrigin`, passed with `PlayTrackRequested` by those pages, `PlayerBloc.origin`) is saved to `SharedPreferences` by `PlaybackSessionStore`. Home's resume card reads it from the player.
- Equalizer: settings, profiles (at most 100) and the phone's last known bands in `SharedPreferences` (`PrefsEqualizerRepository`); a broken value reads as the defaults. Backups carry the settings and profiles under an optional `equalizer` key, read leniently: a broken one is dropped and the rest restores. Restoring merges profiles by id; resetting Settings turns the equalizer off and flat and keeps the profiles.
- Backups (`lib/features/backup/`): JSON files (`BackupCodec`) of the parts the user picks, `BackupPart` (playlists, likes, history as one block, settings, equalizer); a song is described once (title, artist, album, duration, file name and size) and found again on another phone by `TrackMatcher`. A whole backup is format version 1, which older apps read; one leaving parts out is version 2 and lists them under `contents` (a part listed must have its section, an unknown name is skipped). A restore reads the file first, offers the parts it holds with something in them (`BackupSummary`), all ticked, then writes only those (`Backup.only`) and looks only for the songs they name; it merges, so restoring twice changes nothing. Settings, the equalizer and likes are applied by the caller (`restoreBackup`, `restore_flow.dart`) only when kept. Backups go to a folder the user picks once (`SafBackupFolderRepository` over `BackupFolderChannel.kt`, the Storage Access Framework: no storage permission, the files outlive an uninstall; files cross the channel as local paths, never bytes); without one (iOS, or none picked) they are shared and imported as files. Files are named by when they were made and whether automatically (`BackupFileName`, local time; older day-only exports are read too), so listing opens none; their summaries are kept on the phone, counted again when the size changed. The automatic backup (`RunAutoBackupUseCase`, from `AppShell` 5 s after start and on each resume, never in the background) is due once a local calendar day or seven have passed, skips a backup whose fingerprint (FNV-1a of its encoding, date left out) matches the last while that one is still in the folder, and keeps the last 5 automatic ones (`keep`); those made by hand are never deleted. A failed run waits `retryAfter` (1 h) before the next, and a clock before 2024 backs nothing up. Debug builds tag their automatic files (`troona-auto-dev-...`, `StoredBackup.mine`), so the dev and release apps sharing a folder never rotate each other's; a file is written as `.partial` and renamed once whole, and one over `BackupCodec.maxBytes` is refused before it is copied. A folder whose access is gone is `BackupFolderLost`, said once per run by a toast. Preferences (parts, auto, frequency, the last automatic run) and the folder live in `SharedPreferences`, never in a backup. `BackupCubit` (a singleton) runs one task at a time; the automatic backup waits for the next check rather than run beside one.
- Last version whose "What's new" was handled: `SharedPreferences` (`SharedPrefsWhatsNewRepository`). Add a `Release` (version, date as in CHANGELOG.md, notes) to the top of `releaseNotes()` with each version that should show the sheet; the sheet features the installed release and lists the earlier ones.
- Covers extracted from local files are cached in the app cache directory under `troona_artwork_cache`.
- Online extras are opt-in, behind two switches: bios (Last.fm) and photos (Deezer). `MetadataRepositoryImpl` contacts each source only when its switch is on. Their JSON and downloaded photos live under `troona_metadata_cache` (photos in `photos/`), so "clear online info" removes and measures both. Turning photos off deletes the downloaded ones. An artist's photo is taken only from a Deezer song search that finds one of their own songs credited to that name (`DeezerArtistMatch`, with their most played songs they lead, `ArtistArtworkPrefetchService.songTitlesFor`): a name alone finds namesakes, and Deezer's grey silhouette (an empty image hash) is never taken. Photos downloaded before this check are removed once (`forgetUncheckedArtistPhotos`).
- Artist and album pages show About (`OnlineAboutCard`, `lib/features/metadata/presentation/widgets/`) only when Last.fm has a text: counts and tags alone make no card. A read of the artist, their songs or their albums that fails shows the error on a first load and keeps the page on a reload (`ArtistDetailBloc`). Similar artists show only when the library holds them (`SimilarArtistsCubit`, `ArtistDetailRepository.getArtistsByNames`), in Also in your library.

### Design System (Glassmorphism)
Three-level token hierarchy in `lib/core/theme/`:
1. **Primitives**: raw colors, sizes, radii
2. **Semantic**: `bgPrimary`, `accent`, labels; `subtleFill`, `hairline`, `pressedInk` for what is not glass
3. **Components**: `GlassConfig` presets per surface and quality tier (high, low, off). The tier lives in the theme (`GlassSettings`, a `ThemeExtension` every `GlassTheme` accessor reads): `AppThemeBuilder` builds the app's theme from the glass setting, "auto" taking the tier `GlassTier.detect()` found at start-up, so changing the setting redraws every surface; no static quality state. Settings are loaded before the first frame (`injection.dart`), so no frame shows another tier. Tests pick a tier with `AppTheme.withGlass(quality)` (`AppTheme.dark` is high). `GlassCard` is flat by default: blur is for chrome (tab bar, header, sheets, Now Playing), never for cards in scrolling content. The hairline edge is for what floats (tab bar, sheets, round glass buttons, Now Playing's dock, cards that keep one), drawn by one painter, `GlassEdgePainter` (`lib/shared/widgets/glass_edge.dart`: bright at the top, fading down the sides); the collapsed header has none (see below). The floating tab bar casts a shadow painted outside it only, as a foreground painter (`OuterShadowPainter`): in the backdrop, even beside the bar, its blur would take the shadow in. Glass surfaces (bars, header, sheets, cards, lens, dock, round buttons) take their colours from `GlassTheme`, per tier (the lens and the dock have their own presets, `lens` and `nowPlaying`). Small pills and fields (`AppBadge`, `AppToast`, the search field, segmented controls) and `AppColors.subtleFill`, `hairline` and `pressedInk` (fields, opaque dialogs, row ink) stay the same on every tier. content cards (Home's resume card, shortcuts, Recently played, system and recap cards; Settings sections) have the fill alone, grouped by spacing: `GlassTheme.content`, whose fill on the high tier is a step above `card`'s (8 % against 4 %, which needs its edge to show).

Every `BackdropFilter` takes `GlassFilter.of(sigma, saturation: config.saturation, exposure: config.exposure)`, never a bare `ImageFilter.blur` (one filter kept per material, built once). Surfaces that carry text (`GlassTheme.bar` for the tab bar, mini player and `GlassSliverHeader`; `GlassTheme.sheet`) use a middle material, tuned on a Pixel 8: blur 30, a 15 % dark tint and a mild 1.25x saturation. The boost never goes without the tint: on thin glass it turns covers and coloured icons behind into vivid stains. The full 1.6x boost is for decorative glass over artwork (Now Playing lens and dock). The page header takes `GlassTheme.header`: the bar glass with an exposure of 0.5 (`GlassConfig.exposure`, folded into the same colour matrix as the saturation by `GlassFilter.of`), since covers scroll right under its title with nothing to darken them first (the tab bar has the shell's fade); white text keeps about 5:1 over a white cover.

Tiers save by blurring fewer surfaces, never by a smaller sigma (Impeller blurs a large sigma on a smaller image; the cost is the capture, per filter and per pixel). Full (`high`): every glass blurs. Balanced (`low`): the page header alone, at full strength (sharp text passes under its title); the tab bar is an 88 % tint of `bgTertiary` with its edge, the lens and the dock a veil, sheets opaque: at most one blur on screen. No blur (`off`): none; bars a 94 % tint, cards and sheets `bgElevated`, edges kept (palette tints, never iOS grey). Below Full the background follows a song in 380 ms everywhere (`DynamicBackground.transitionOf`). Detection falls back to Balanced when Android's hardware cannot be read; iOS gets Full. Settings name the tiers Auto, Full, Balanced, No blur, and say which one Auto picked.

`BackdropFilter` performance rules (enforced throughout):
- Always wrap in a `RepaintBoundary`.
- Never place inside an `AnimatedBuilder` that rebuilds on audio position.
- Maximum two `BackdropFilter`s on screen at once (the Now Playing page already uses both, so sheets over it are opaque). A page's header and the tab bar are the two; the header's blur keeps one sigma and is only enabled once content passes under it (`BackdropFilter.enabled`), and a push or pop between two collapsed headers shows three for the length of the transition on Full glass. On Balanced one shows: a page pushed opens expanded, so a push never makes two; a header that goes away (popped, or on top while a back swipe drags it off) takes the opaque tint for the transition, only when the page it reveals blurs, so the page that stays keeps its glass throughout; a swipe called off hands the blur back once the page has slid back (`_GlassLayer` reads its route's animation and the navigator's gesture).
- One exception: a short-lived modal sheet over the shell (the tab bar blurs below it, a collapsed header may too) may add a third blur on high-tier devices only. `showGlassBottomSheet` gets its quality from `GlassTheme.aboveGlass(context)`, read from the context it is opened from: opaque on low-tier devices, when the user turns glass down, and below a `BlurBudgetSpent` (`lib/core/theme/components/blur_budget.dart`). Now Playing and the content of every sheet are marked with it, so the queue, its menus and a sheet opened from a sheet are opaque. Not for anything that stays on screen.

Modals and labels go through one entry point each, in `lib/shared/widgets/`; never `showModalBottomSheet`, `showCupertinoModalPopup`, `showDialog` or a Cupertino sheet or dialog directly:
- `showGlassBottomSheet`: every bottom sheet (queue, What's new, add to playlist).
- `showActionSheet` with `SheetAction`s: every menu of actions or options (track actions, sort, sleep timer, speed). A tap closes the sheet, then runs the action.
- `app_dialog.dart` (`showConfirmDialog`, `showMessageDialog`, `showTextInputDialog`): opaque, fade and scale in, fade only when animations are reduced.
- `AppToast`: every transient message.
- Haptics go through `AppHaptics` (`lib/core/utils/haptics_helper.dart`, which states the vocabulary), never `HapticFeedback`. An `InkWell` with a long press sets `enableFeedback: false`, or the system's buzz doubles the menu's tick; a menu ticks as it opens, not the row that opens it. Playback ticks once, in `PlayerBloc`: a button that sends a playback event adds none.
- `SwipeActions`: every horizontal swipe that runs an action (a tick once armed, then it springs back). Song rows wrap it in `QueueSwipe` (right plays next, left adds to the queue). The one exception is the mini player's song, a carousel (`_MiniPlayerRowState`; nothing in the row is keyed by song, so a song change keeps the cover's image until the new one is decoded): the titles follow the finger with the neighbour's coming in, each fading with its distance, both edges faded while they move (`EdgeFade`, `lib/shared/widgets/edge_fade.dart`: a mask layer only while active, the same tree either way), while the cover stays and cross-fades to the new song's; the drag's way and threshold read the finger from where it began, never the titles (still settling after a change); past the threshold or flung, it jumps by queue index (`QueueIndexRequested`, wrapping only under repeat all, as the Now Playing covers: never `Queue.nextTrack`, the song itself under repeat one) and the titles slide on once the player gets there, or come back after `_patience`; meanwhile Next and other swipes wait, and a song changing under the finger ends that drag. Only a change asked for in the mini player slides (a swipe, its Next button); one from elsewhere (a song ending, Now Playing, the queue) and every change with reduced motion fade in place. A swipe down on the mini player closes it, then the player stops (`PlayerDismissed`); up, fast, opens Now Playing. Over the tabs, the bar's top edge follows the finger and the row comes down over them (the bar's column is listed bottom up, so the mini player paints last), dissolving from its bottom up (`_DropOut`, `dropOutMaskAt`), gone before it reaches the bar's bottom edge, with nothing left to shrink once idle. Alone (a pushed page), the bar slides down whole, glass and all, off the screen, without fading (`_NavBarBody._slideOut`). The drop is drawn around the row's `AnimatedSize` (inside, it would be clipped and eased), so its controller lives in the bar's state and the row drives it; the tree is the same with tabs or without, so the heroes below survive the switch. Both ways go through the row's one `GestureDetector`: a second vertical recognizer (a `Dismissible`) never wins against it. A long press on the mini player likes the song (a heart over its cover, a light tick, a toast); Next keeps its button. A like answers with one animation wherever it is made (`LikeBurst`, `lib/shared/widgets/like_burst.dart`): over the mini player's cover, over Now Playing's heart (with a light tick), over a song row's cover or number when liked from its menu (`showTrackActions(onLikeToggled:)`). Only where the gesture was made, never on every place showing the song. A whole album or artist is queued in one event, `TracksQueued`, through `queueSongs`, one song through `queueSong` (`lib/features/player/presentation/utils/queue_songs.dart`, which toasts once the player confirms: the events carry `onQueued`, run only when the songs are in, not refused, not played instead, not into a queue replaced meanwhile, which also gets no `TrackQueued`); with nothing loaded (`PlayerIdle`, as after the mini player is swiped away: the engine keeps a dead queue, never edited), queueing plays instead (the list from its first song, or the one song), and no toast says it was queued; a first song still loading has its queue waited for, until it fails (a queue being replaced counts once the requested song is current, `_requestedTrackId`). They go to the engine in one call, `AudioServicePort.addAllToQueue` (just_audio's `insertAudioSources`), all or none: nothing can come between them. Songs queued by hand (not Undo putting one back) make `PlayerBloc` emit one `TrackQueued(count)` per action once the player took them; the mini player's cover pulses once and counts them (`_QueuedAck`, its count held in the row's state), the shell shows no toast for it (the action already did).
- Picking songs: one selection app-wide, `TrackSelectionCubit` (a singleton, provided in `main.dart`), owned by the list it was started in. A page wraps its list, header included, in `TrackSelectionScope` (`lib/features/library/presentation/widgets/selection/`) with its songs in the order shown (Library Songs through `enabled`, album, playlist, artist with all their songs folded or not, artist songs, Recently added, Search: its results, else its suggestions). Rows read `TrackSelectionScope.statusOf` and go through `longPress` and `tap`: a long press starts picking (light tick; it closes the keyboard), then taps pick or let go (selection tick) instead of playing; outside a scope the long press opens the menu. Rows name both for screen readers (`TrackSelectionScope.hintsOf`, as their tap and long press hints), and on iOS each pick reads the count out (VoiceOver ignores its live region). While picking, a row shows `SelectionMark` over its cover (an album row fades its number), hides its options button (its room kept) and its swipes (`QueueSwipe(enabled:)`); a playlist row hides its handle, which alone moves a row. The header's navigation row shows `SelectionBar` (end, `RollingCount`, Select all) through `GlassNavOverride` (a header with no navigation row, Search's, shows it over its pinned bottom, the field), and the floating bar's bottom row shows `SelectionActions` (`AppBottomNavBar.actions`: over the tabs, or over the mini player on a pushed page, so the bar keeps its height; alone, on a pushed page with nothing playing, it slides off once done instead of vanishing), both cross-faded over what stays mounted below (`CrossFadeSwap`). Actions take the songs in the list's order and end the selection (Add to playlist only once songs were added: the ones the playlist lacks go in one write, all or none, `PlaylistRepository.addTracksToPlaylist`, and Undo takes them back in one, `removeTracksFromPlaylist`). The system back ends it first, through a `BackButtonListener` under the router, only while the page is on top (a sheet or Now Playing over it closes instead); never a `PopScope` that cannot pop, which turns the edge swipe back off: the swipe leaves the page, which ends it. The root of a navigator (a tab root) keeps the `PopScope`: it has no swipe to lose, and a route that cannot pop is what tells Android that the app takes the back press (`setFrameworkHandlesBack`; else Android 16 leaves the app). The root navigator reports its own routes only (after a sheet over the shell closes, say), so `SelectionPlace` also keeps the shell's route from popping while picking, as go_router does for a tab with pages pushed. So do the scope going away, a route or tab change (`SelectionPlace` in `AppShell`, keyed by location and tab), the last song let go.
- `AppBadge` (neutral) and `AppBadge.accent`: small pill labels.
- `AppButton.primary`, `.secondary` and `.text`, in two sizes: `small` (32 dp pill, in-line actions such as See all) and `medium` (44 dp, the default). Both take at least 44 x 44 dp, the touch target. Never a raw `TextButton`, `FilledButton`, `OutlinedButton` or a `GestureDetector` pill; the dialog actions and the boot failure screen are the exceptions. Play and Shuffle on album and playlist pages are one widget, `PlayShuffleButtons`; the artist page has Shuffle alone, as a round button (`ShuffleRoundButton`, same file): an artist's songs have no order.
- `AppBackButton`: the back button of every pushed page (glass circle), the `leading` of its `GlassSliverHeader`. In an `AppBar`, also set `leadingWidth: AppBackButton.leadingWidth`.
- Icon-only buttons: `GlassIconButton` for a glass circle (header actions), `AppIconButton` for a bare icon (row options, sheet close, field clear, mini player). `AppIconButton` takes 44 x 44 dp and requires a tooltip, the label screen readers read. Never a raw `IconButton`.

In song rows the duration and the options button are `labelSecondary`. Every label level used for text reads at 4.5:1 on the page's black (tertiary at half alpha, `label_contrast_test.dart`); over the brightest point of a glow, tertiary falls to about 4:1, so it is for what can be missed (counts, dates), never the only label of an action. A switch that is on is `accent` on every Settings row, whatever its icon's colour; the Library filter marks its choice in `accent`, never the song's palette. Round means an artist or something turning, never an album at rest: artists are circles (cards, rows), drawn by `ArtistAvatar` (their downloaded photo, else their cover, else their initials; a photo downloaded while on screen shows at once; it carries the photo's hero unless `hero: false`, for a second circle of one artist on a page, as Search's top result), and so are the covers of what plays (Now Playing's stage, the album page's record) and the orb at the centre of the tab bar; an album at rest, anywhere, is a rounded square. Album and artist cards carry `PlayingBadge` (an equalizer on the cover while the current song is theirs; for an artist, any credit), outside the cover's hero. The album page's record (`_AlbumVinyl`) slides further out of its sleeve and turns while its album plays, a tap on it pauses or resumes that album (it never starts it), and pulling the page down draws it out further with the finger (`albumRecordPullOut`, the main scroll view's overscroll read through `_AlbumPull`, so only the record rebuilds). Opening the album that plays brings the song's row to the middle of what the mini player leaves once the page is in (and Now Playing gone, when opened from it: `NowPlayingHero.coverAnimation` back to null), when it lies below the screen and the list has not moved (scrolled, or the record pulled out) (`_AlbumTracksView`): rows far down are not built, so it aims from the nearest built row, again from closer, then from the row itself; a touch on its way stops it; at once with reduced motion. Rows are measured where the list lays them out (the list's own child: a viewport's reveal offset is thrown off by the pinned header, and the row's entrance moves the row itself), and found by song id. An album's menu, from a long press on its card or its page's options, is `showAlbumActions` (`album_actions.dart`; the page leaves out Play and Shuffle, its buttons). The centre of the tab bar is `PlayingOrb` (`lib/features/player/presentation/widgets/playing_orb.dart`), a sphere painted in the colours of the song playing (`PlayingOrb.colorsFor`, from the palette's two background colours; a grey cover stays grey), the accent with nothing loaded. It is a button, never decoration: the bar reports a tap as `AppTab.player` and the host decides (`OrbAction`): the shell opens Now Playing while a song is loaded, else resumes the saved session, else shuffles the library; Now Playing closes itself. It moves at moments only (its colours swirl to a new song's, one pulse on play and pause) and runs no ticker at rest: the bar is glass, and a perpetual animation inside it would have every blur on screen computed again on each frame. A song's cover in a list row is `TrackRowArtwork` (`lib/features/library/presentation/widgets/track_row_artwork.dart`): the current song's is dimmed under the `MiniEqualizer`, still while paused; numbered album rows show the equalizer in place of the number.

Artwork is decoded at its displayed size through `ArtworkImage` (`lib/shared/widgets/artwork_image.dart`). A null or empty path, or a file that cannot be read, shows `ArtworkPlaceholder` with the role's icon (`placeholder: AppIcons.album`), opaque like a cover; never a hand-made grey box.

Icons come from `AppIcons` (`lib/core/theme/semantic/app_icons.dart`), named by role, not by glyph. It is the only file that imports an icon pack (Lucide, plus Eva for the filled glyphs Lucide lacks) or names `CupertinoIcons` or Material `Icons`, which `test/unit/architecture/icon_sources_test.dart` enforces (the boot failure screen may use Material `Icons`). Give each role its own entry, even when two roles share a glyph (a playlist and the queue).

### Library Scanning (4-phase)
`MediaScannerService` orchestrates: (1) query device via `on_audio_query_pluse`, (2) diff against cache to find added/removed tracks, (3) persist to `IsarLibraryDataSource`, (4) extract artwork via `ArtworkExtractor` (semaphore × 4 for concurrency control).

A missing artist (Android's `<unknown>`, older "Unknown Artist") is stored and passed around as `''` (`TrackTags.unknownArtist`, `lib/features/library/domain/services/track_tags.dart`); screens show it with `context.artistName(...)`, which reads "Unknown artist" in the app's language. When a song has none, `TrackModel.nameMissingArtist` reads it from an "Artist - Title" file name (`TrackTags.fromName`, which returns null when in doubt); a real title tag is never split.

Artists and albums are rebuilt from the whole library on every scan (`TrackModel.link`, after phase 1), not taken from MediaStore:
- Artists are keyed by name: `artistId` is `TrackTags.artistIdFor(name)`, never a MediaStore id (MediaStore gives every distinct artist tag an id, so "A" and "A, B" were two artists).
- A song credits every artist its tag names (`artistNames`, `artistIds`; `Track.credits` in the domain), read by `ArtistCredits.of(allTags).split(tag)` (`artist_credits.dart`): "feat."/"ft." always separate, a comma only when one of the names around it is an artist of its own somewhere in the library, "&" and "/" never. A whole comma tag with no known name in it ("Tyler, The Creator") is one artist, also inside longer lists, until one of its parts is set apart by a list it is not in. `artistId` is the first credit. An artist page holds every song that credits them, their albums (they are the album's artist), their singles and, apart, the albums they appear on (`ArtistAlbums`, `LibraryGrouping.albumsOfArtist`), each newest first, the undated ones last; Latest release shows their newest album or single (`ArtistAlbums.latest`), none without a year or under four releases (`latestFrom`); under five releases, albums and singles make one Discography, singles marked, newest first (`ArtistAlbums.oneDiscography`, `discography`); a section of one or two albums lists them as rows (`AlbumRow`, `_ArtistAlbumsCarousel.carouselFrom`), not a lone card in a carousel; "More by" on an album page lists their own albums, then their singles; its songs come most played first (`ArtistSongs.ranked`, all-time plays from `PlayHistoryRepository.playCounts`), five shown before See all, which unfolds up to 20 in place and opens more on `ArtistSongsPage` (`artists/:id/songs`, a sibling of the artist route, not nested, or the pushed page would bring a copy of the artist page), sorted by plays, title, album or date added (`ArtistSongOrder`); the Artists list leaves out artists only ever credited as guests (`LibraryGrouping.artistsOf`, `guests: true` in search).
- Without an album artist tag, MediaStore makes one album per name and folder, and downloaders save an album across folders ("Album (1)", "Album (2)"). `AlbumMerge` joins MediaStore albums of the same name that share an artist credited on all their songs, however they chain, and never cuts one (a compilation stays whole). An album with an artist gets `TrackTags.stableId(name + lead artist)`, so its id survives folders coming and going; a compilation keeps its MediaStore id.
- Ids made by `TrackTags.stableId` are negative 64-bit FNV-1a hashes; MediaStore ids are positive.
- Songs in the player queue keep the ids they had when queued: "Go to album/artist" reads the song again from the library first (`show_track_actions.dart`). A song's artist opens through `openArtistOf` (Go to artist, the Now Playing artist line): one credit opens at once, several ask which one in an action sheet. From where no page context names the tab (a sheet, Now Playing once closed), album and artist pages open with `pushDetailInTab(router, ...)`, in the tab shown, handed the page shown as `extra` (`shownPage`: the last pushed match in the tabs' shell, Now Playing left out; the router's own location keeps the last `go`, a tab root); the page already shown stays, and the page it was opened from is popped back to; never `goNamed`, which jumps to the Library and replaces its stack. An album carries its artists as `Album.credits` (from `LibraryGrouping`; an album read without its songs falls back to `artist` and `artistId`); its page shows them as one line, a 44 dp link that opens the one artist or asks which (`AlbumArtistLinks`; links side by side wrapped over the header's facts). Never split `Album.artist` on commas, a name may hold one.
- An artist's name and cover come from their song added first to the phone (the lowest id; the cover from the first that has one), whatever order the songs are read in: the Library reads every song, an artist's page their albums by track, and both must show the same artist (`LibraryGrouping._artist`).
- An album's artist is the artists credited on every one of its songs, none for a compilation (`LibraryGrouping`). An album of one song belongs to its first credit only, or its guests would own it. Every screen builds albums and artists through `LibraryGrouping`, so counts and names agree.
- MediaStore has no release type: an album of at most three songs named after one of them is a single (`SingleRelease.matches`, `Album.isSingle`), comparing names without brackets, " - " parts or featured artists. `Artist.albumCount` leaves singles out; `singleCount` counts them. No EP is told apart: four songs may be half an album downloaded.
- Phase 2 calls `refreshIndexed`: indexed rows take every field the scan read (tags, size, duration, year, dates) and the links above; covers and `indexedAt` are kept. A retagged file is picked up and a row stored wrong heals. The year comes from MediaStore as text (`TrackModel.fromSongModel`).
- An album page lists its whole track list, never folded, in `AlbumOrder.sorted` order: disc and track number (MediaStore files the disc in the thousands), then the order files were added, since downloaded songs often have no number. `AlbumOrder.numbers` shows the track numbers only when every song has one, else the places. A song's artist line shows only when the album's artist does not say it all (`LibraryGrouping.creditLine`).

### Misc
- Debug and profile builds install as `com.donfreddy.troona.dev` ("Troona Dev", DEV banner icon from `android/app/src/debug/res/`), next to the release app and with their own data. To bring real data over, export a backup from the release app and restore it in the dev one. Settings shows a Debug section in non-release builds (`DebugSection`): make this month's Replay now, show "What's new" on the next launch.
- GitHub release descriptions start from `.github/RELEASE_TEMPLATE.md` (its comments list the checks before publishing).
- App is **portrait-only**: `android:screenOrientation="userPortrait"` in the manifest, and an unawaited `SystemChrome` call in `main.dart` for iOS. Nothing before `runApp` may await a platform channel that needs an activity: `audio_service` can run `main()` with none.
- Dark theme only (`ThemeMode.dark`).
- No design-size scaling: layouts follow the room they get (`LayoutBuilder`, `Expanded`). Now Playing shrinks its ring on short screens. Fixed-height chrome (tab bar and mini player, segmented controls, Now Playing and its queue, the navigation row and `pinnedBottom` of `GlassSliverHeader`: Library filter, Search field) caps the font size at `AppLayout.maxTextScale` (1.3, `lib/core/layout/app_layout.dart`) with a local `MediaQuery.withClampedTextScaling`; everything else follows the phone's font size and wraps or stacks instead of overflowing. Content under the floating bar pads with `context.bottomBarInset()`.
- Layout is checked at 360 x 640 dp (Galaxy S7 class) with the font at 1.3 and 2.0, as well as on tall phones. Layout tests that measure labels load Roboto (`test/helpers/roboto.dart`).
